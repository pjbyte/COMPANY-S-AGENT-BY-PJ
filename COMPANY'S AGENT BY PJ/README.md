# Company's Agent by PJ — Agentic RAG Knowledge Assistant for Enterprise Policies

> Ask your company's HR / IT / expense policies in plain English. Get grounded answers
> with page-level citations, retrieved by **hybrid search**, generated by **Gemini**,
> and audited for hallucinations by a **LangGraph agent loop**.

**Verified result: 100% retrieval hit-rate@5 on a 22-question golden QA set** (run
`scripts/evaluate.py` yourself — the report lands in `reports/eval_report.md`).

## ⚡ How to run (Windows)

1. Install once: [Python 3.11+](https://www.python.org/downloads/) and [Node.js LTS](https://nodejs.org/)
2. Download this project (**Code → Download ZIP**, then extract) — or `git clone` it
3. Double-click **`start.bat`** inside the extracted folder — it installs everything
   on first run, starts the app, and opens your browser automatically
4. For full AI answers: copy `backend\.env.example` to `backend\.env` and paste your
   free key from [aistudio.google.com/apikey](https://aistudio.google.com/apikey)

> **Note:** code on github.com cannot be executed — download the project first, then
> run it from your PC. If Windows SmartScreen warns you about `start.bat`, click
> *More info → Run anyway* (it's a plain script you can read in any text editor).

Detailed setup (manual commands, Linux/macOS, Docker, AWS) is in
[Quickstart](#quickstart) below.

## What it does (the 30-second demo)

1. Upload company policy PDFs (three realistic samples are included).
2. Ask *"How many annual leave days do I get and how many carry forward?"*
3. The agent: **rewrites the query → routes it → retrieves 5 chunks (hybrid search + rerank) → grades them → writes a cited answer → audits it for hallucinations.**
4. The UI streams the answer with citation chips `[1] Employee Leave Policy · p1` — click one to read the exact chunk. The agent's whole decision path is shown as step pills.

## Architecture

```
                        ┌────────────────────────────────────────────┐
                        │                React UI (Vite)             │
                        │  chat · streaming · citations · agent trace │
                        └───────────────┬────────────────────────────┘
                                        │ SSE / REST
                        ┌───────────────▼────────────────────────────┐
                        │              FastAPI backend               │
                        │   /chat  /documents  /feedback  /stats     │
                        └───────────────┬────────────────────────────┘
                                        │
        ┌───────────────────────────────▼────────────────────────────────┐
        │                     LangGraph agent loop                       │
        │                                                                │
        │  rewrite_query ──► route ──► retrieve ──► grade_documents      │
        │                                   ▲            │               │
        │                                   │ retry      ▼               │
        │                                   └──── generate ──► audit ──┐  │
        │                                            ▲                 │  │
        │                        stricter rewrite ───┘ (if ungrounded)  │  │
        │  fallbacks: web_search (labelled) · "I could not find..."     │  │
        └───────────────┬──────────────────────────────┬────────────────┘
                        │                              │
        ┌───────────────▼──────────┐    ┌──────────────▼─────────────────┐
        │      Hybrid retriever    │    │      Gemini (free tier)        │
        │  vector (ChromaDB) +     │    │  generation · routing ·        │
        │  BM25 (rank_bm25) → RRF  │    │  grading · hallucination audit │
        │  → cross-encoder rerank  │    └────────────────────────────────┘
        └───────────────▲──────────┘
                        │
        ┌───────────────┴──────────┐
        │      Ingestion           │  PDF ─► text (PyMuPDF) ─► section-aware
        │                          │  chunking ─► embeddings (MiniLM) ─► store
        └──────────────────────────┘
```

**Anti-hallucination, three layers:** (1) the prompt allows only the numbered chunks,
(2) an LLM grader discards irrelevant chunks before generation, (3) an auditor checks
every claim against sources and forces one stricter rewrite if it finds unsupported
claims. If nothing relevant is found at all, it says so instead of guessing — and can
fall back to clearly-labelled web search.

## Tech stack

| Layer | Tools |
|---|---|
| LLM | Gemini 2.5 Flash (free tier, `google-genai` SDK) |
| Agents | LangGraph (state machine with conditional edges + retry loops) |
| Embeddings | sentence-transformers `all-MiniLM-L6-v2` (local, free) or Gemini embeddings |
| Vector DB | ChromaDB (persistent, cosine) |
| Keyword search | BM25 (`rank-bm25`) fused via Reciprocal Rank Fusion |
| Reranking | cross-encoder `ms-marco-MiniLM-L-6-v2` |
| Parsing / chunking | PyMuPDF, section-aware overlapping chunks (900/150) |
| API | FastAPI, Server-Sent Events streaming, SQLite (sessions, messages, feedback) |
| Frontend | React 18 + Vite, citation chips, agent-trace bar, drag-drop upload |
| Deployment | Docker + docker-compose (nginx reverse proxy, SSE-aware), AWS EC2-ready |

## Quickstart

**Prereqs:** Python 3.11+, Node 18+, and (for full AI answers) a free [Gemini API key](https://aistudio.google.com/apikey).

### Option A — Windows, one click

Double-click **`start.bat`**. It installs dependencies on first run, builds the UI,
starts the server, and opens the app at **http://localhost:8000** automatically.
Stop it with **`stop.bat`** (or by closing the minimized server window).

For full AI answers, put your key in `backend\.env` (copy `backend\.env.example`)
and restart. Without a key the app runs in **demo mode**: retrieval, citations and
the agent trace work; the answer lists the best-matching passages instead.

> Opening `frontend/index.html` directly in a browser will **not** work — a React app
> needs its build step and the API server behind it. Always start via `start.bat`.

### Option B — manual / development mode

```bash
# 1. Backend
cd backend
python -m venv .venv
.venv\Scripts\activate                 # Windows  (Linux/macOS: source .venv/bin/activate)
pip install -r requirements.txt
copy .env.example .env                 # then paste your GEMINI_API_KEY inside

python scripts/make_sample_policies.py # create 3 sample policy PDFs
python scripts/ingest.py               # parse -> chunk -> embed -> index

uvicorn app.main:app --reload --port 8000

# 2. Frontend with hot reload (new terminal)
cd frontend
npm install
npm run dev                            # http://localhost:5173
```

The production build (`npm run build` in `frontend/`) is served by the backend itself
on port 8000 — one process, one URL.

### Docker

```bash
cp backend/.env.example backend/.env   # add your key
docker compose up --build              # UI on http://localhost, API on :8000
```

### AWS EC2 deployment (matches the AWS skills on a typical resume)

1. Launch an Ubuntu t2.micro/t3.small, open ports 22/80/8000.
2. Install Docker, clone the repo, `docker compose up --build -d`.
3. Free-tier caveat: t2.micro has 1 GB RAM — set `RERANK_ENABLED=false` and use
   `EMBEDDINGS_PROVIDER=gemini` there, or run on a t3.small.

## Evaluation

```bash
python scripts/evaluate.py --retrieval-only   # no key needed: hit-rate@k
python scripts/evaluate.py                    # + full agent answers, LLM-as-judge
```

- **Retrieval hit-rate** — does the expected document *and* section appear in top-k?
  (22/22 = 100% at k=5 on this corpus.)
- **LLM-as-judge** — scores every generated answer for *faithfulness* (is every claim
  supported by the sources?) and *correctness* (does it match the reference?) — the
  same metrics the popular RAGAS library measures, implemented transparently.
- **Agent telemetry** — per-question trace (steps taken, retries, audit verdict) and
  end-to-end latency are recorded in `reports/eval_results.json`.

Talk about these numbers in interviews: *"I built an eval harness with a golden QA set,
measured hit-rate@5, and used LLM-as-judge for faithfulness — that's how I knew my
section-aware chunking change was what fixed retrieval."* (That change really did lift
top-1 accuracy; see `core/ingestion.py`.)

## Engineering highlights

- Production-style agentic RAG: PDF ingestion → section-aware chunking → hybrid
  retrieval (ChromaDB + BM25 + Reciprocal Rank Fusion + cross-encoder reranking) →
  cited, streamed answers (FastAPI, React, Docker).
- Self-corrective LangGraph agent (query rewriting, routing, relevance grading,
  hallucination auditing with automatic regeneration) that refuses to answer from
  missing context, with a labelled web-search fallback.
- Evaluation harness (golden QA set, retrieval hit-rate@5, LLM-as-judge
  faithfulness/correctness) that drove the chunking design — **100% hit-rate@5** on
  the demo corpus at ~120 ms retrieval latency.
